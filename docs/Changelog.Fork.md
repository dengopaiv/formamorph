# 📝 Changelog — this fork

The work that happens in **[dengopaiv/formamorph](https://github.com/dengopaiv/formamorph)** and not upstream.

`docs/Changelog.md` beside this file is **[JakeJamesDev's](https://github.com/JakeJamesDev/formamorph)**, and is left exactly as he writes it — nothing from this fork is ever added to it. That is what keeps it readable as his own record and what makes a rebase onto upstream conflict-free: a file we never touch cannot collide. Read it with `git show upstream/main:docs/Changelog.md` to see his line without checking anything out.

The original is **[FieryLionite's Formamorph](https://fierylion.itch.io/formamorph)**, the JavaScript app this whole tree descends from. Its repository still carries a changelog, but it has not moved on its own since 2025-10-31 — the one commit after that merges Jake's version in — so what is there is his text, older. `git show fierylionite/main:docs/Changelog.md`.

Sections follow upstream's shape so the two read alike: **Major** / **Minor**, then **Added** / **Removed** / **Fixed**, and within those by audience — 👤 user-facing · 🛠️ developer tooling · ⚙️ backend.

## 🚧 In Progress

_Unreleased. Versions are upstream's to pin; entries accumulate here until the work they describe is settled._

### Minor Changes

#### ➕ Added

- **👤 User-facing**
  - **The World Editor's ✨ drafting buttons run on a prompt you can open and edit, with their own output caps.** The three buttons that draft one description from another — **Player-Facing** from AI-Facing, **AI-Facing** from Player-Facing, and **Summary** from AI-Facing — each ran on wording built into the app, at a length nothing could reach. A model that wrote too floridly for a reference field, or that stopped mid-sentence because the draft ran past four hundred tokens, could only be worked around by rewriting what came back. Settings → **Prompts** gains an **Authoring** group carrying all three, each in the same editor every other prompt in that panel uses — full screen, undo, variable chips — and each with its own **Max Output Tokens**. The caps start where the fixed ones sat, four hundred tokens for the two descriptions and eighty for the summary, so nothing changes until you move them; a summary can now be held to a single line while a description is given the room to finish its last sentence. Two chips are offered. **`<SUBJECT>`** stands for the thing being described, so one prompt serves the location, entity and trait editors alike and reads correctly in each, and **`<FACETS>`** for the aspects worth covering. The chips that fill from a turn in progress are deliberately absent, because no turn is in flight while you are editing a world — there would be nothing to put in them. The group appears in **Advanced** mode, and like every prompt in that panel it is edited on a preset of your own: the built-ins stay read-only until you duplicate one, and **Reset** on any of the three restores its wording *and* its cap together, since a prompt asking for three sentences and a cap sized for three sentences are one setting in two boxes. All three travel inside a shared prompt preset, so a set tuned for a small local model can be handed to someone else along with the rest.
  - **The 🔍 check stopped asking a question no model could answer.** It used to look for a third thing besides the two disagreements: an AI-Facing description that had stopped saying any more than the Player-Facing one, which is what a reference note looks like after it has been overwritten from the blurb. It was the reason the button existed, and across five models and four wordings of the question it was found once in ninety-six tries — while asking for it made every other finding noisier, because the only thing the wording ever changed was how much the model said. It is gone, and the Author's Brief answers it properly by making that round trip impossible rather than detectable. What the button reports now is what it was always reliably good at: a fact the two state differently, and a fact the Player-Facing description states that the AI-Facing one never accounts for. Findings arrive faster and there is more room in the output cap for the ones that are real. That second question is also asked more plainly than it used to be — the removed bullet turned out to have been propping it up, and cutting it on its own made the button miss roughly a quarter of the gaps it had been catching, so the wording that remains now says outright that a fact the player is shown and the note does not hold is a fact the narrator cannot use. Measured back to where it was and past it on one of the two models tested. Your own edited copy of the prompt is untouched — this changes the shipped default, which **Reset** restores.
  - **A field of your own that nothing writes into: the Author's Brief.** The World Editor's two descriptions could each be drafted from the other, which meant neither was a base — and because the Player-Facing prompt is meant to hold private material back while the AI-Facing prompt is meant to fill in what a blurb implies, drafting in both directions in turn stripped your secrets and put a model's guesses in their place, in the field the narrator reads, in prose indistinguishable from your own. **Entities, locations, traits and trait groups now open with an Author's Brief above both descriptions, and no ✨ button on it — nothing in the app ever writes there.** Put what is true in it, in whatever shape suits you: a list is expected rather than prose, because turning a list into sentences is the work the drafting buttons are for. Both ✨ buttons then draft from the brief instead of from each other, so either description can be regenerated as many times as you like and what you wrote stays exactly as you wrote it. Mark a line **SECRET:** and the Player-Facing draft leaves it out while the AI-Facing draft keeps it — which is the difference between those two descriptions in the first place. A description that comes back wrong is fixed by correcting the brief and pressing ✨ again, rather than by rewriting the prose every time. Nothing changes for a world you have already written: a subject with an empty brief drafts exactly as it did before, Player-Facing from AI-Facing and AI-Facing from Player-Facing. The brief travels with a shared character card too, so whoever receives it inherits the source and not only the prose.
  - **The two descriptions can be read against each other now, and replacing one says what it costs.** The World Editor's ✨ buttons draft the Player-Facing description from the AI-Facing one, and the AI-Facing one back from the Player-Facing — which means neither of them is a base, and drafting in both directions in turn does not return you to where you started. The player-facing prompt is *meant* to withhold: secrets, plans and private history stay out of what a player reads. The AI-facing prompt is *meant* to fill in what a blurb implies. Run one into the other and back, and the private material is stripped on the way out and replaced on the way in by whatever the model thought fit — in the field the narrator actually reads, in prose indistinguishable from your own. Two things answer that. **A ✨ button that would replace writing already in the field asks first**, naming the field and how many sentences go; generating into an empty one is still a single click, because nothing can be lost there. And **a 🔍 button beside the AI-Facing Description reads the two against each other**, reporting a fact one states and the other contradicts, something the blurb asserts that the note does not account for, or an AI-facing description that has stopped saying any more than the player-facing one — which is what a reference note looks like after it has been overwritten from the blurb. It writes nothing at all: every finding is yours to act on or ignore, and the report opens in a dialog you can read at your own pace rather than a message that fades while you are still on it. Its wording is a prompt like any other, in Settings → **Prompts** → **Authoring** → **Description Check**, with its own output cap.
  - **An endpoint that would send your writing across the internet unencrypted now says so.** What this app hands a text endpoint is the world, the characters, the scene as it stands and the model's reply — and over a plain `http://` address to a machine out on the internet, all of it crosses every hop in between as readable text, along with the API token in the header. Nothing said so before. Settings → **Endpoint URL** now carries a warning under the field when the address is `http://` and the host is genuinely remote, on the image endpoint as well as the text one — what that receives is the scene rendered into a prompt, which gives away no less than the prose it came from. It is a warning and not a refusal: the app cannot tell an unwise endpoint from a deliberate one, only refuse to let the choice be made silently. **Nothing local is flagged.** Loopback, a LAN address, a `.local` name and a Tailscale address are all silent, because `http://` inside a tunnel or a WireGuard mesh is already encrypted underneath and warning about those would only teach you to click past the warning that matters. Screen-reader users get it on the field itself rather than as loose text beside it: the warning is named in the input's description, so focusing the box reads it out.
- **🛠️ Developer tooling**
  - **The authoring prompts compose through token substitution rather than branching, and their caps ride the prompt-preset store.** `lib/bridgeDescription` exports its two default templates beside `composeBridgePrompt`, which resolves `<SUBJECT>` and `<FACETS>` against the direction being generated — so one editable template covers both directions, and the wording that differs between them lives in a record keyed by direction instead of inside a string literal nobody could reach. `lib/summarize` took the same override shape, and both gained a `template` and a `maxTokens` option that fall back to the shipped defaults, leaving every existing caller unchanged. The caps are stored as a `descTokens` map on `PromptPreset` and read through `activeDescTokens`, which layers a preset over its base exactly as the prompt text already did — so sharing, migration and reset came free rather than being written a second time: `promptPresetShare` enumerates `PROMPT_TEXT_KEYS`, and the three new keys were picked up by adding them to that list. `promptGroups` single-sources `isAuthoringTab`, which `SettingsModal` uses to keep the **Options** surface off these tabs — that pane resolves its tuning through `TAB_TO_REQUEST`, and a prompt that runs outside a turn has no `AIRequestType` to resolve to. The prompt-variable invariant that every kind offers the six shared context chips is now scoped to the turn-pipeline kinds, with a complementary test asserting the authoring kinds offer none of them, so the rule that used to be "always" is now two rules that each say why.
  - **The description-consistency work starts at the pass that cannot damage anything.** `lib/descriptionCheck` is a report-only sibling of `bridgeDescription` — same request shape, same editable-template contract — and its `parseFindings` is lenient on purpose: small models bullet their lists, number them, or hedge with a trailing NONE, and none of that changes what was found, so bullets and numbering are stripped and a lone NONE becomes the empty list. Agreement is a *result*, not a failure, which is why an empty completion resolves to no findings rather than throwing the way the drafting calls do. `lib/descriptionOverwrite` holds the rule the warning is built on: generating into an empty field cannot lose anything, so only an overwrite is ever interrupted — and closing the round trip requires one every single time, which is what makes warning on overwrites alone sufficient. It counts sentences rather than words because the authoring prompts are themselves written in sentences (*"Write 2 to 4 sentences"*), so the number reads against what was asked for; it is knowingly loose on abbreviations, and nothing branches on the count. The fourth authoring prompt registered itself exactly as the first three did — one entry each in `DescPromptKind`, `PROMPT_TEXT_KEYS`, `AUTHORING_TABS` and `PROMPT_KIND_VARIABLES` — and the two tests that enumerate the authoring kinds now enumerate `AUTHORING_TABS` rather than a written-out list, so the next one is held to those rules by arriving rather than by being remembered.
  - **The description round trip is answered by a base field rather than by detection, because detection was measured and does not work.** `lib/descriptionCheck` was built first, on the theory that a model could be asked whether an AI-facing description had been laundered from the blurb. Across five models from 24B to frontier, four prompt variants and roughly 1,400 probe calls, that finding was named in **one run out of ninety-six** — and every rewrite of the prompt moved a single dial, how much the model says, with true and false positives rising and falling together. A model cannot reliably notice that something private is *absent*. `authorBrief` removes the question instead: an optional field on `Trait`, `TraitGroup`, `Entity` and `GameLocation` that no generator writes to, turning the description graph from a cycle into a star rooted at authored text. `lib/authorBrief` holds the rule in one place — `draftSource` returns the brief when it has anything and otherwise the other description, which is the entire migration story: an absent field reads as "no brief" and every existing world drafts exactly as it did. The invariant that no ✨ button is ever placed on the brief is asserted by a test that renders the editor and attributes each generate control to the field it sits on, rather than being left to review. Measured alongside: bullets are as good a source as prose — `bridge-probe.mjs --source brief` scores 94–95% fact recall and zero secret leaks drafting from a bullet list on both a frontier model and a 24B roleplay finetune, against 94% and 90% from the existing prose sources.
  - **The omission bullet was measured after the round-trip bullet was cut, and it needed the cut bullet's framing back.** Removing a request for a finding that arrives once in ninety-six looked free. It was not: on the same fixtures and seeds, omission detection fell from 100% to 75% on deepseek-v4-flash and 74% to 58% on cydonia-24b-v4.1, in the same direction on both. The removed bullet — *"detail the AI-facing description ought to hold and does not"* — had been asking the omission question a second time from the note's side, and was priming it; it was doing two jobs, one it never accomplished and one it did by accident. The repair was not to put it back, which would restore a request for a finding that measurably never arrives, but to fold the note-side framing into the bullet that remains. That bought the detections back — flash 75% → 88%, cydonia 52% → 78%, pooled 30/47 → 39/47 at Fisher p = 0.03 — with the clean arm unmoved and no extra call. Both the module note and a test pin the second sentence in place, because trimming it as redundant is exactly the edit that was already tried and costs twenty points. The clean arm is untouched by any of this and remains the reason the button is not finished: 88–100% false positives on both models, before and after.
  - **`desccheck-probe.mjs` runs the check against pairs whose disagreement is known before the model sees them.** The unit tests can prove the parser survives a bulleted list; only a real endpoint can say whether a model returns findings at all rather than a rewrite, or says NONE when the two agree instead of inventing a disagreement to be useful. The cast is the bridge probe's four subjects unchanged, so a result here can be read beside how the drafting prompts behaved on the same text, and each subject runs four arms: the two descriptions as authored, which genuinely agree — then one fact changed on the player side so it contradicts the note, one fact added that the note never accounts for, and a note laundered down to saying no more than the blurb, which is the round trip's own signature and the finding the whole feature exists for. **The arm that matters most is the one where nothing is wrong**: an author shown three imaginary problems stops opening the dialog. Because the probe scores through the shipped `parseFindings` rather than a copy of it, it can tell a model that invented a disagreement apart from one that said the two agree in prose the parser then kept as a finding — the second is a parser gap with a different fix, so the two are counted separately. A run that comes back empty with the token budget spent is voided rather than scored, since `checkDescriptions` reads an empty completion as agreement and a null result must not be able to pass as a clean one. Several `--model` values run as arms over the same fixtures and seeds and print one table, which is the point: a frontier arm says whether the prompt is *right*, and only a small-model arm says whether it *survives* the model this app is usually pointed at.
  - **`endpointSendsInTheClear` decides that in one place, and is deliberately quiet twice.** It is true only for `http://` to a host outside loopback, RFC1918, link-local, IPv6 unique-local, `.local` and the `100.64/10` CGNAT block Tailscale hands out — that last one because a Tailscale address is WireGuard-encrypted regardless of the scheme in front of it, so flagging it would be a false alarm on a correct setup. It is also silent on input that does not parse, since the field is evaluated on every keystroke and half a URL is not yet a mistake. Both Endpoint URL rows render the warning through `aria-describedby`; the image row gained `top` and `data-row-stacked` for the reason `SettingsModal.alignment` asserts — a row whose extra line is conditional grows only sometimes and has to be aligned for both states, which the DOM at any one moment cannot decide.
